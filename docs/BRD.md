# BRD - 레거시 인사 데이터 통합 및 사내 규정 기반 연차 관리 시스템

## 1. 프로젝트 개요

### 1.1 프로젝트명

레거시 인사 데이터 통합 및 사내 규정 기반 연차 관리 시스템

### 1.2 배경

원천별로 인사 데이터의 구조와 표현 방식이 달라 데이터 활용을 위한 확인·정제 작업이 반복되고 있다. 또한 사내 복지 연차의 적용 기준과 부여 주기가 다양하여 직원별 연차 계산과 이력 관리에 오류가 발생할 수 있다.

### 1.3 목적

원천 인사 데이터를 보존·표준화하고, 검증된 데이터를 기반으로 사내 규정에 따른 추가 연차를 계산·부여·관리한다.

## 2. 비즈니스 문제 정의

1. 원천별 인사 데이터의 구조와 표현 방식이 일관되지 않다.
2. 데이터 확인·정제·검증 작업이 반복된다.
3. 직원별 추가 연차 계산과 중복 여부를 수작업으로 확인한다.
4. 연차 부여 결과와 적용 근거를 일관되게 관리하기 어렵다.

## 3. 프로젝트 목표

| 단계 | 목표 | 우선순위 |
|---|---|:---:|
| Bronze | 원천 데이터를 변경 없이 보존하고 처리 이력을 추적한다. | Must |
| Silver | 인사 데이터를 표준화하고 품질을 검증한다. | Must |
| Gold | 연차 산정에 필요한 목적별 데이터를 구성한다. | Must |
| Service | 담당자가 추가 연차를 계산·부여하고 이력을 관리한다. | Must |

## 4. 이해관계자와 역할

| 이해관계자 | 역할 |
|---|---|
| 인사 담당자 | 데이터와 규정 적용 여부를 확인하고 추가 연차를 부여한다. |
| 인사 책임자 | 데이터 기준과 사내 복지 규정을 승인한다. |
| 데이터·시스템 운영 담당자 | 데이터 처리, 품질 및 부여 이력을 관리한다. |

## 5. 프로젝트 범위

### 5.1 포함 범위

- 원천 인사 데이터 수집 및 원본 보존
- 인사 데이터 정제·표준화·품질 검증
- 연차 산정용 Gold 데이터 구성
- 직원 정보와 현재 잔여 연차 조회
- 담당자의 적용 규정 직접 선택
- 추가 연차 자동 합산 및 결과 확인
- 부여 결과 저장 및 직원별 이력 조회
- 동일 규정의 중복 부여 확인

### 5.2 제외 범위

- 규정 충족 여부의 자동 판정
- 연차 신청·승인·취소 및 사용 처리
- 원천 시스템의 데이터 직접 등록·수정
- 사내 복지 규정 자체의 등록·변경
- 급여·근태·평가 등 전체 HR 시스템 구축

## 6. 비즈니스 요구사항

| ID | 우선순위 | 비즈니스 요구사항 |
|---|:---:|---|
| BR-001 | Must | 승인된 범위의 원천 데이터를 변경 없이 보존하고 추적할 수 있어야 한다. |
| BR-002 | Must | 승인된 용어·형식·코드에 따라 데이터를 표준화할 수 있어야 한다. |
| BR-003 | Must | 품질 기준에 따라 정상 데이터와 추가 확인 데이터를 구분할 수 있어야 한다. |
| BR-004 | Must | 검증된 데이터로 연차 산정용 Gold 데이터를 구성할 수 있어야 한다. |
| BR-005 | Must | 담당자는 직원을 검색하고 연차 부여에 필요한 정보를 확인할 수 있어야 한다. |
| BR-006 | Must | 담당자가 선택한 규정별 부여 일수와 총 부여 일수를 계산할 수 있어야 한다. |
| BR-007 | Must | 추가 연차 부여 결과와 적용 근거를 저장·조회할 수 있어야 한다. |
| BR-008 | Must | 동일 규정의 중복 부여를 확인할 수 있어야 한다. |

상세 데이터 기준과 사내 복지 규정은 [BRD Appendix](BRD_Appendix.md)를 따른다.

## 7. 성공 기준

| 구분 | 정량 성공 기준 |
|---|---|
| Bronze | 승인된 원천 데이터의 보존율 100% |
| Silver | 승인된 대상 필드의 표준 매핑률 100%, 핵심 품질 오류 0건 |
| Gold | 승인된 연차 규정 테스트의 기대 결과 일치율 100% |
| 계산 | 선택한 규정별 부여 일수와 총합 계산 오류 0건 |
| 저장 | 검수 대상 부여 결과의 저장·조회 성공률 100% |
| 중복 방지 | 동일 규정·동일 적용 기간의 중복 부여 0건 |

상세 산식, 품질 기준 및 테스트 사례는 Appendix에서 관리한다.

## 8. 주요 위험 및 전제

### 8.1 주요 위험

- 원천 데이터의 의미와 관계가 불명확할 수 있다.
- 데이터 누락·오류로 연차 산정 대상이 제한될 수 있다.
- 담당자의 수동 판단에 따라 규정 적용 결과가 달라질 수 있다.
- 규정별 적용 기간 차이로 중복 부여가 발생할 수 있다.

### 8.2 핵심 전제

- 승인된 원천 데이터가 제공된다.
- 인사 담당자는 데이터와 규정 검토에 참여한다.
- 데이터 품질 기준과 사내 복지 규정은 검수 전에 승인한다.
- 추가 복지 연차의 적용 여부는 담당자가 직접 판단한다.
