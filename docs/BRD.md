# BRD - 레거시 인사 데이터 통합 및 조건 기반 복지연차 일괄 부여 서비스

## 1. 프로젝트 개요

### 1.1 프로젝트명

레거시 인사 데이터 통합 및 조건 기반 복지연차 일괄 부여 서비스

### 1.2 배경

원천별로 인사 데이터의 구조와 표현 방식이 달라 데이터 활용을 위한 확인·정제 작업이 반복되고 있다. 또한 사내 복지 연차의 적용 기준과 부여 주기가 다양하여 직원별 연차 계산과 이력 관리에 오류가 발생할 수 있다.

### 1.3 목적

원천 인사 데이터를 보존·표준화하고, 검증된 데이터를 기반으로 사내 복지 연차 규정에 따라 대상자를 조회하고, 특정 직원 또는 조회된 전체 대상자를 선택하여 복지 연차를 부여한다.

## 2. 비즈니스 문제 정의

1. 원천별 인사 데이터의 구조와 표현 방식이 일관되지 않다.
2. 데이터 확인·정제·검증 작업이 반복된다.
3. 복지 연차 대상자를 엑셀에서 개별적으로 조회·선별하고 부여 내역을 수작업으로 관리하고 있다.
4. 대규모 대상자에 대한 복지 연차 부여와 이력 관리가 어렵다.

## 3. 프로젝트 목표

| 단계 | 목표 | 우선순위 |
|---|---|:---:|
| Bronze | 원천 데이터를 변경 없이 보존하고 처리 이력을 추적한다. | Must |
| Silver | 인사 데이터를 표준화하고 품질을 검증한다. | Must |
| Gold | 복지 연차 대상자 조회에 필요한 목적별 데이터를 구성한다. | Should |
| Service | 조건에 따라 대상자를 조회하고, 선택한 대상자에게 복지 연차를 부여하며 이력을 관리한다. | Should |

## 4. 이해관계자와 역할

| 이해관계자 | 역할 |
|---|---|
| 인사 담당자 | 부여 조건에 따른 대상자를 조회·검토하고, 복지 연차를 부여한다. |
| 인사 책임자 | 데이터 기준과 사내 복지 규정을 승인한다. |
| 데이터·시스템 운영 담당자 | 데이터 처리, 품질 및 부여 이력을 관리한다. |

## 5. 프로젝트 범위

### 5.1 포함 범위

- 원천 인사 데이터 수집 및 원본 보존
- 인사 데이터 정제·표준화·품질 검증
- 복지 연차 대상자 조회용 Gold 데이터 구성
- 부여 기준과 세부 조건에 따른 대상자 조회
- 대상 인원 및 직원 정보 확인
- 조회 결과 내 이름·직원아이디 검색
- 특정 직원 또는 전체 대상자에 대한 복지 연차 부여
- 부여 결과 저장 및 직원별 이력 조회
- 동일 기준·적용 회차의 중복 부여 확인

### 5.2 제외 범위

- 근태·성과·출산 등 제공되지 않은 정보를 기준으로 한 대상자 자동 판정
- 현재 잔여 연차 조회·계산 및 기존 인사시스템의 공식 연차 잔액 반영
- 연차 신청·승인·취소 및 사용 처리
- 원천 인사시스템의 데이터 직접 등록·수정
- 사내 복지 연차 규정의 등록·변경
- 급여·근태·평가 등 전체 HR 시스템 구축

## 6. 비즈니스 요구사항

| ID | 우선순위 | 비즈니스 요구사항 |
|---|:---:|---|
| BR-001 | Must | 승인된 범위의 원천 데이터를 변경 없이 보존하고 추적할 수 있어야 한다. |
| BR-002 | Must | 승인된 용어·형식·코드에 따라 데이터를 표준화할 수 있어야 한다. |
| BR-003 | Must | 품질 기준에 따라 정상 데이터와 추가 확인 데이터를 구분할 수 있어야 한다. |
| BR-004 | Should | 검증된 데이터로 연차 산정용 Gold 데이터를 구성할 수 있어야 한다. |
| BR-005 | Should | 담당자는 직원을 검색하고 연차 부여에 필요한 정보를 확인할 수 있어야 한다. |
| BR-006 | Should | 담당자가 선택한 규정별 부여 일수와 총 부여 일수를 계산할 수 있어야 한다. |
| BR-007 | Should | 추가 연차 부여 결과와 적용 근거를 저장·조회할 수 있어야 한다. |
| BR-008 | Should | 동일 규정의 중복 부여를 확인할 수 있어야 한다. |

상세 데이터 기준과 사내 복지 규정은 [BRD Appendix](BRD_Appendix.md)를 따른다.

## 7. 성공 기준

| 구분 | 정량 성공 기준 |
|---|---|
| Bronze | 승인된 원천 데이터의 보존율 100% |
| Silver | 승인된 필드의 표준화 처리율 95% 이상, Reject 사유 기록률 100% |
| Gold | 승인된 대상자 선별 테스트의 기대 결과 일치율 100% |
| 조회 | 인사 데이터 51,250건 기준 대상자 수 및 첫 페이지 조회 5초 이내 |
| 부여 | 최대 51,250건의 복지 연차 부여 내역 처리 1분 이내 |
| 저장 | 부여 결과의 저장·조회 성공률 99% 이상 |
| 중복 방지 | 동일 규정·동일 적용 기간의 중복 부여 0건 |

상세 산식, 품질 기준 및 테스트 사례는 Appendix에서 관리한다.

## 8. 주요 위험 및 전제

### 8.1 주요 위험

- 원천 데이터 오류로 대상자 조회 결과가 부정확할 수 있다.
- 조건 설정 오류로 대규모 오부여가 발생할 수 있다.
- 일괄 부여 재실행으로 중복 이력이 생성될 수 있다.
- 제공 데이터의 한계로 적용 가능한 복지 연차 규정이 제한될 수 있다.

### 8.2 핵심 전제

- 승인된 원천 데이터가 제공된다.
- 인사 담당자는 데이터와 규정 검토에 참여한다.
- 데이터 품질 기준과 사내 복지 규정은 검수 전에 승인한다.
- 인사 담당자는 시스템이 조회한 대상자를 확인한 후 최종 부여한다.
